# NAS 真机部署

> 本文是原开发设备的部署及功能演进记录，含该设备 IP、路径和历史测试说明。新部署先阅读 [通用部署说明](../docs/deployment.md)。当前功能以主 README 为准，历史报告和照片未随公开仓库提供。

测试设备：`192.168.1.80`，fnOS / Docker，i7-6820HQ、16GB RAM、Quadro M2000M 4GB。应用入口：`http://192.168.1.80:8766/`。飞牛应用中心和桌面入口名为“有宠相簿”，应用 ID 为 `ousepet`。

## 文件与数据

- 部署目录：`/vol1/1000/OusePet`。
- Compose：`compose.yaml`、`compose.gpu.yaml`。
- 镜像：`ousepet-album:0.1.0-cu124`。

## GPU 与网页设置

网页右上角“设置”提供“GPU 加速”开关。开启时优先使用 CUDA，无法使用时自动回退到 CPU；关闭时使用 CPU。偏好保存在 SQLite `settings` 表，重启后保留。正在处理照片时，等待当前照片完成后切换设备。界面显示的是实际使用的设备。

服务诊断：`GET /api/settings`、`GET /api/runtime`。健康检查：`GET /api/health`。Docker 自动健康检查已启用，容器设置为 `restart: unless-stopped`，资源限制为 4 CPU / 4GB RAM。

CUDA 环境使用 PyTorch 2.6.0 + CUDA 12.4 / torchvision 0.21.0，实测包含该显卡所需的 `sm_50`。安装来源参见 [PyTorch 官方历史版本](https://docs.pytorch.org/get-started/previous-versions/)。GPU 使用 NVIDIA 官方 Container Toolkit 1.20.1 生成的 CDI 配置接入，无需重启 Docker 守护进程。工具解包在部署目录的 `gpu-tools/`，配置位于 `/etc/cdi/ousepet-nvidia.yaml`；参考 [NVIDIA CDI 文档](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/cdi-support.html)。

NAS 更新显卡驱动后，如 CDI 中的驱动库版本失效，可重新生成：

```bash
sudo /vol1/1000/OusePet/gpu-tools/usr/bin/nvidia-ctk cdi generate \
  --nvidia-cdi-hook-path /vol1/1000/OusePet/gpu-tools/usr/bin/nvidia-cdi-hook \
  --output /etc/cdi/ousepet-nvidia.yaml
cd /vol1/1000/OusePet
docker compose -f compose.yaml -f compose.gpu.yaml up -d --force-recreate --no-build
```

## 服务管理与更新

可直接在飞牛应用中心启动、停止应用。命令行等价操作：

```bash
sudo appcenter-cli status ousepet
sudo appcenter-cli stop ousepet
sudo appcenter-cli start ousepet
```

运行中断的扫描会在服务启动后自动恢复，复用已完成的照片索引与识别结果；用户暂停的扫描保持暂停。

扫描为增量处理：首次扫描识别全部未处理照片，后续只处理新增、修改或尚未完成识别的文件。每个文件夹默认开启自动增量，后台每 60 秒检查一次（`OUSEPET_WATCH_INTERVAL` 可配置），无需打开网页；自动检查暂缓处理最近 5 秒仍有写入的文件。未变化照片只比对修改时间和大小，不重新哈希或识别；重复内容不会重复入库，重复文件路径也会缓存。无变化不创建空任务。任务进度的总数指本次待处理文件数，图库总数在图库页查看。

存储管理支持“移除”。`DELETE /api/storages/{id}` 将存储标记为已断开、关闭自动增量并取消运行／排队／暂停的扫描，原图和索引不删除。该存储的照片在图库、收藏、宠物详情和相册中隐藏，对应数量和封面同步更新；另一已连接存储中的同内容照片继续显示。再次添加同一路径复用原存储 ID，开启自动增量，恢复识别缓存、命名、手动归属和排除记录、收藏、相册关系，只处理新增／变化／未完成文件。移除期间当前单张识别最多完成这一张，不会继续扫描或自动重新连接。验证：`scripts/test_storage_removal.py` 覆盖重导入、无重复哈希／推理、原图保留、重复来源、父目录导入和扫描中移除。

自动识别结果直接归档，不再提供“待确认”导航、角标或确认身份操作。误分时在宠物档案中移出照片，漏分时从图库或存储中添加；这些人工修改会保留。旧 `?view=review` 入口转为宠物图库；后台保留自动／人工来源信息以延续历史数据，不要求用户再确认。

“设置 → 数据管理”提供两种操作：“重新扫描文件夹”通过 `POST /api/library/scan` 为所有已连接文件夹安排增量检查，保留整理结果；“清空数据并重新识别”通过 `POST /api/library/reset` 提交后台重建，需要输入 `清空并重新识别` 确认。清除照片索引、识别特征、宠物档案和命名、手动归属／排除记录、收藏、相册、缩略图、任务历史及已断开存储缓存，保留原图、已连接文件夹配置和 GPU 设置，然后自动创建全量扫描任务。

清空前将数据库备份到 `data/backups/album-before-reset-*.sqlite3`，备份不携带待执行的清空标记。旧运行、排队、暂停及发现任务先取消，清空工作与推理使用同一单线程队列，确保旧推理不会在清空后写回；清空期间暂拒绝写操作和存储浏览索引，自动检查暂缓。清空状态持久化，服务中断后恢复，进度通过悬浮球和扫描任务查看；失败可在设置中重试。实际原图不会被删除或修改。`scripts/test_library_reset.py` 使用隔离数据验证确认、队列取消、旧结果隔离、备份、全量重建、配置保留和重启恢复；浏览器脚本只在隔离服务实际执行清空，NAS 上只做只读验证。

任务列表中的已完成、已取消、出错和中断记录支持单条删除，底部“清空历史记录”会清理全部历史（包括当前列表 15 条之外的记录）。运行、排队和暂停任务优先显示且不允许直接删除，需先取消。清理只影响任务列表，不影响照片、识别结果、存储设置；数据库保留隐藏的终态标记，避免清理最新记录后在重启时误恢复更早的中断扫描。

“扫描任务”内支持暂停、继续和取消。取消后保留已完成结果，正在识别的单张照片最多完成当前这一张，不会继续下一张，也不会把“已取消”覆盖成“已完成”。取消同时关闭该文件夹的自动增量，避免未处理照片立即重新排队；在“存储管理”的“自动增量”开关可恢复。关闭自动增量不影响手动扫描。重复点击扫描不会创建同一文件夹的并行任务。文件夹内原图不会被修改或删除。

验证脚本：`scripts/test_incremental_scan.py` 使用隔离数据库、真实文件和可控识别验证增量、重复文件、自动发现、并发排队、三种状态的取消及设置持久化；`scripts/check_scan_controls.py` 使用隔离服务及实际浏览器验证桌面和手机上的取消与自动增量开关。`scripts/album_api_check.py` 验证真实模型识别及已有相册功能。

fnOS FPK 是这台 NAS 的桌面和服务控制包，依赖上述部署目录、已构建镜像及模型。0.1.1 的入口按 [飞牛官方应用入口文档](https://developer.fnnas.com/docs/core-concepts/app-entry/) 使用 `type: url`，默认在独立标签页或外部 Web 视图打开，直接占满页面，避免飞牛桌面导航与相簿导航同时显示。复用已有 `8766` 端口，无需新增服务。卸载入口包不会删除部署目录中的数据库、原图和模型。

直接访问 `http://192.168.1.80:8766/` 为完整图库，`/?view=gallery` 为宠物图库，`/?view=cats`、`/?view=hedgehogs` 为物种筛选；页面切换会同步地址并支持刷新、前进和后退。桌面右上角可一键进入浏览器全屏；浏览器要求用户点击后才能隐藏浏览器工具栏，不能靠路由参数自动进入。底部“我的宠物时光”文字已移除，物种筛选统一放在图库内，设置统一保留右上角入口。

0.1.2 将垂直滚动限制在相册内容面板内，外层页面、搜索框和侧栏固定；切换分类或搜索时回到内容顶部。搜索框改为自适应宽度的长胶囊，仍按宠物名称、文件名或拍摄日期匹配，不表示已支持自然语言语义搜索。图标使用 `assets/branding/logo-rounded-v2.png` 的透明圆角版本，打包时同时更新桌面图标和网页 favicon。

图库内的物种选项位于标题右侧、排序按钮之前，宠物筛选在下方独立横向滚动，头像与名称不压缩为竖排；长名称省略显示并提供完整标题。扫描和宠物发现进度使用右下角悬浮球，滚动时位置固定，显示百分比／排队或暂停状态，点击打开任务列表，所有任务完成后消失。悬浮球在照片层前、照片查看器及弹窗层后，内容底部预留空间。`scripts/check_pet_filters.py` 使用 40 个分组及长名字验证桌面、平板和手机布局、键盘滚动、筛选点击、悬浮位置、弹窗层级及任务状态切换。

选中第一张照片后进入多选模式，点击图片任意位置可切换选中状态，所有日期分组的选中标记同时可见；此时隐藏缩略图收藏按钮，避免误操作。取消全部选择或点击选择工具栏的关闭按钮后恢复点击预览。`scripts/check_photo_selection.py` 验证桌面、手机、键盘与整图点击，且不写入 API。

照片结果绑定当前视图、宠物／相册、搜索和排序条件，切换时不展示上一个条件的照片，晚到的旧请求无法覆盖当前结果。宠物档案列表本身不再请求无筛选的图库照片，慢请求期间显示加载状态，失败可重试。合并完成后停留在宠物档案列表，保留目标名字；从列表发起合并时保留滚动位置。`scripts/check_photo_navigation.py` 通过延迟和交错请求、浏览器返回与失败重试逐帧检查错误照片闪现；`scripts/check_pet_discovery_ui.py` 验证合并后的列表视图、目标名字、照片数量及来源档案消失。

自动发现的规则和增量扫描说明统一放在“设置”中，档案列表不再显示说明横幅。设置同时提供键盘操作说明：Esc 按层关闭当前弹窗或照片预览、退出多选，再返回上一级；宠物详情返回档案列表，相册详情返回相册列表。照片预览支持左右方向键，Ctrl／⌘ + A 选择当前已加载的照片，`/` 聚焦搜索框。输入框保留原有键盘操作；搜索中按 Esc 清空搜索。下拉菜单与对话框先处理 Esc，不会同时触发父级返回。`scripts/check_keyboard_navigation.py` 对桌面、手机、弹窗层级、快捷键和说明位置进行只读浏览器验证。

宠物发现现已接入：检测猫咪、刺猬区域后，提取本地 DINOv2 特征，按物种分开做宽松的相似分组。每组至少 5 张不同照片才生成“未命名猫咪／刺猬”，不足 5 张暂不展示。重复内容不会重复计数，同一张照片中检测到的不同宠物不会合为一组。已有图库在升级后自动补提取特征，进度可通过右下角悬浮球打开扫描任务查看、取消；重启会复用已提取的特征，用户取消后需点击“发现宠物”才能恢复补处理。新扫描到的宠物照片会同步提取特征；命名保留分组 ID，新增相似照片继续直接归档，误分可移出、漏分可手动添加。

宠物卡片提供编辑名字／种类，以及多选合并；宠物详情支持批量“移出此宠物”，照片详情也可移除身份。合并保留目标名字、既有确认结果和多个分组的参考特征；不同物种不能合并。同照片中独立检测的两组宠物在首次合并时返回 409 冲突及照片列表，界面展示缩略图，可在新标签页打开原图。用户确认同一只后可继续合并（`confirm_conflicts: true`），共享照片只计一次；未确认时不修改档案。移出身份会记录排除关系，避免重新提取后回到同一档案。相似度不是身份概率：外观近似的宠物仍可能误分，同一宠物不同姿势也可能分成多组，需要用户命名、合并和纠正。不会按物种直接把所有猫归入“基米”、所有刺猬归入“扣嘚”。

宠物卡片支持“删除”，确认后通过 `DELETE /api/pets/{id}` 原子移除档案及其身份关联。原图、照片记录、收藏和相册关联保留；自动分组标记为已忽略，保留匿名特征以防后续扫描或补处理重新生成该分组。空档案也可删除，不会在启动时重新创建。已有照片需要重新归档时，仍可手动添加到其他宠物档案。

实现位于 `ousepet/identity.py`，特征缓存、分组、排除关系与补处理进度保存在 SQLite，原图只读。使用固定参考、组中心、最近样本和候选差距联合约束以减少链式误合并。特征匹配阈值是优先召回的启发式，不是已校准的身份认证精度。`scripts/test_pet_discovery.py` 和 `scripts/check_pet_discovery_ui.py` 验证完整流程；`scripts/evaluate_identity_groups.py` 对已有标注裁剪特征做诊断，结果不等同于独立准确率测试。

导航和下拉框的只读浏览器验证：`.venv-smoke/Scripts/python.exe scripts/check_album_navigation.py`。覆盖桌面与手机布局、路由恢复、全屏、菜单键盘选择和 Esc 焦点恢复，截图与结果位于 `reports/nas/`。

更新前端和 Python 代码后，先在本机执行 `npm.cmd --prefix frontend run build`，将变更文件同步至 NAS，再构建并更新自己的容器：

```bash
cd /vol1/1000/OusePet
DOCKER_BUILDKIT=0 docker build --network host \
  --build-arg HTTP_PROXY=http://127.0.0.1:20171 \
  --build-arg HTTPS_PROXY=http://127.0.0.1:20171 \
  -f Dockerfile.album -t ousepet-album:0.1.0-cu124 .
docker compose -f compose.yaml -f compose.gpu.yaml up -d --no-build
```

代理地址是 NAS 上现有代理，仅用于构建。NAS 的 Docker Hub 直连失败时，本次通过本机 WSL 下载基础镜像、`docker save` 传输到 NAS 后 `docker load`，没有修改全局 Docker 代理或重启其他容器。

## 验证记录

同一张猫咪和两张刺猬照片，预热后各测三轮：CPU 中位数约 1.27 秒/张，GPU 约 0.55 秒/张，约 2.3 倍。计时包含检测与物种验证，输入图片已解码，不代表整库扫描速度。两种设备的这三张照片检测结果一致。GPU 张量峰值约 180MB，实际进程还占用 CUDA 上下文、缓存等显存。

原始数据：NAS `data/benchmark-cpu.json` 和 `data/benchmark-gpu.json`；本机 `reports/nas/` 保留对比、网页操作和部署检查记录。`scripts/check_nas_web.py --mode cpu|gpu` 可以通过真实浏览器切换设备并验证偏好和实际运行设备。

设置界面采用独立全屏面板，桌面左侧分类、右侧内容，默认文件夹管理；包含 AI 设置、显示设置、数据管理和使用帮助，手机分类栏横向滚动、右侧内容独立滚动。文件夹管理支持添加、扫描全部／单个文件夹、自动增量开关及移除，添加／移除对话框结束后返回设置；Esc 关闭设置返回原相册位置。重建操作继续使用独立输入确认窗口。布局、分类、下拉层级和手机适配由 `scripts/check_settings_scan_controls.py`、`scripts/check_album_navigation.py` 和 `scripts/check_keyboard_navigation.py` 只读验证。

图库首批加载 200 张，滚动接近相册面板底部时自动继续加载，每次增加 200 张，并显示“已加载／总数”，避免首屏分页末尾被误认为漏扫早期照片。失败保留已加载照片，停止自动重试并提供手动重试；切换宠物、搜索和排序后恢复独立分页状态。`scripts/check_photo_pagination.py` 使用 450 张隔离数据验证跨年照片续载、错误重试、完整数量及搜索重置，NAS 验证只读、不重新扫描或清空。

右侧照片时间轴通过 `GET /api/photos/timeline` 获取当前筛选下所有月份的数量和起始位置，首批照片未加载完也能看到完整年份范围。年份／月份按钮或竖向日期滑杆可直接跳转，只读取目标位置附近照片；滑杆拖动显示年月提示，方向键与 Home／End 也可定位。滚动时跟随高亮当前年份，搜索、宠物、相册、物种和排序共用同一筛选条件；弹窗／预览打开时隐藏时间轴。普通续载提前约 1200px 请求下一批并追加，不重新读取此前所有照片。`scripts/check_photo_timeline.py` 验证索引、直接跨年、月份与键盘定位及手机布局，`scripts/check_timeline_live.py` 只读验证 NAS 实际旧年份跳转。

身份匹配升级为 `recall-v2`，优先归档：新增照片采用最近样本 0.78、组中心 0.70、固定参考 0.66、候选差距 0.004；已有小组按最近样本 0.76、中心 0.68、固定参考 0.64 做批量扩展。先匹配已有档案，再将不足 5 张但外观相近的小组合并为可展示的档案，不重新提取已完成的 DINOv2 特征。保留档案 ID、名字、原有照片关联、确认和排除记录，已删除分组不复活；猫和刺猬分开，独立共现区域不自动合并。

自动补入的小组标记为非参考，不作为下一轮的跳板，避免反复发现导致链式扩散。用户命名／显式合并后确认其参考组，手动添加的照片也作为参考；这些操作以及扫描结束后会触发复用特征的重新匹配（已取消发现时保持取消）。“发现宠物”也可主动重新归并，任务阶段显示“正在归并已有照片”。宽松匹配有更高误分风险，这是用户明确选择的取舍，不代表身份准确率。

`scripts/test_identity_recall.py` 验证小组归并、命名和手动参考、排除和删除、共现保护、参考防扩散与物种隔离；`scripts/evaluate_recall_tuning.py` 只在真实数据库副本上统计归档覆盖，不改在线数据，覆盖率不等于准确率。当前副本猫归档由 49/667 提高到 205/667，截图所示既有 29 张档案扩至 108 张；刺猬由 145/622 提高到 570/622。在线更新前备份原数据库，启动后自动补匹配，原图与收藏／相册保留。

宠物档案和相册详情的“添加照片”（包括空状态入口）直接打开宠物图库多选器，支持名字／日期搜索、宠物和种类筛选、跨筛选保留选择、整图点击、选择已加载照片，已有成员标记“已添加”。确认后批量加入当前档案／相册并留在原位置，保留原照片归属；超过 500 张分批提交，失败保留未完成选择供重试。存储管理仍可浏览原始文件夹。`scripts/check_photo_picker.py` 使用隔离服务验证空状态与标题入口、相册／宠物、错误重试、去重、超过 500 张批量、键盘和手机布局。

档案列表支持勾选圆圈进入多选，随后整张卡片切换选择，Ctrl+A 全选、Esc 退出。选中至少两个同种类档案后点击“合并宠物”，从选中档案中指定保留者，其名字／ID 保留，来源档案的照片去重归入目标，成功后留在列表。`POST /api/pets/merge` 在单个事务中验证并合并全部来源，统一检查来源之间及来源与目标的共现冲突，确认前不修改任何档案；明确确认后可覆盖重复检测误报。混合种类需先编辑更正。

编辑档案可修改猫咪／刺猬，未命名档案允许不输入名字只改种类，自动更新“未命名猫咪／刺猬”名称。更正同步修改该档案的身份分组和区域种类，以及关联照片的种类，标记人工修正，避免未变化文件扫描或旧推理覆盖；共享照片中其他宠物／独立区域的种类保留。收藏、相册、档案 ID 和原图不变。`scripts/test_pet_bulk_species.py` 验证事务、来源间冲突、混合／失效校验、种类纠正与持久化；`scripts/check_pet_bulk_ui.py` 验证多选合并、详情修改种类、返回位置、快捷键和手机界面。

宠物档案标题栏“排序”支持置顶、上移、下移，保存到服务端 settings.pet_order，多设备和重启后保留；新发现的档案追加到末尾，删除／合并的旧 ID 自动忽略。取消或 Esc 不保存草稿，列表和筛选器使用统一顺序。同框照片可同时添加至猫咪和刺猬档案，分别移出只影响对应档案；自动检测仍可能漏识别，需要手动补入。`scripts/test_pet_order_shared.py` 验证排序持久化、新档案、无效请求及同框双重归属独立；浏览器验证置顶、上下移动、保存、取消与手机布局。

排序弹窗加宽至 780px，去掉提示小字，放大头像和列表行。鼠标按下即捕获指针，移动超过 8px 或按住 350ms 开始拖动，避免鼠标先移动便取消长按；触摸长按 350ms 后拖动整行，未激活时移动超过 8px 仍作普通滚动。浮层跟随指针并保留占位，靠近列表上下边缘自动滚动。松手结束，仍需点击“保存顺序”才写入服务端，取消／Esc 丢弃草稿；保留按钮供键盘操作。`scripts/check_pet_bulk_ui.py` 使用真实鼠标及浏览器原生触摸事件验证头像／名字／拖动柄、直接拖动及长按、单指滚动、边缘自动滚动、取消清理与保存。

档案卡片只保留“编辑”和“删除”，多选通过卡片左上角勾选进入，再使用顶部“合并宠物”。“编辑档案”统一修改名字、种类、封面，“更换封面”打开该宠物专属的单选选择器，支持搜索和继续加载。选好返回编辑页，保留名字／种类草稿，统一点击“保存档案”才通过 PATCH 在单个事务中提交，取消不写入任何草稿。封面固定展示；照片移出档案或断开存储后自动回退到可见照片。同框照片可分别设为不同宠物的封面，预览信息栏也提供对应入口。服务端仅接受档案内可见照片，失效封面会阻止整份编辑提交。隔离测试验证取消不保存、草稿保留、持久化和手机布局。

编辑档案使用 780px 桌面双栏布局，左侧大封面、右侧名字和种类；手机上下排列。封面预览完整显示图片，点击整张预览可更换，去掉底部说明小字。

“相册”在界面中更名为“回忆”，保留原 albums 路由／表和已有内容。回忆卡片支持编辑名字和封面、删除；勾选多个后使用顶部“合并回忆”，指定保留者，照片去重汇入，保留目标名字和封面并留在列表。回忆详情可多选移出照片。移出或删除回忆不删除原图，不影响宠物归属、收藏和其他回忆。封面单独存储于 album_covers（外键级联清理），编辑和合并均有事务与失效校验。

照片选择器（添加照片及宠物／回忆封面）右侧共用完整日期时间轴，按当前筛选获取全量月份与偏移，显示当前年月，可通过年份／月份或日期滑杆直接读取目标区间，每批 200 张；跨日期选择保留，可返回更近照片，选择器内部滚动且手机保留时间轴。`scripts/check_memories.py` 在隔离数据库和真实浏览器验证回忆编辑／封面持久化、原子合并、删除／移出保留原图、手机界面、直接跳转未加载旧年与跨日期添加；`scripts/check_photo_picker.py` 回归多选、失败重试和超过 500 张的分批添加。

视频支持 MP4/MOV/M4V/MKV/AVI/WebM/MTS/M2TS/3GP。照片和视频统一在图库，默认混合显示，标题栏“全部／照片／视频”筛选共用搜索和日期时间轴，不增加独立侧栏入口；media=image/video 参数同步用于列表和月份统计，旧 view=videos 链接兼容进入图库的视频筛选。扫描先索引视频元数据，再逐个识别，让完整视频列表先出现在图库；仅识别到宠物的内容进入宠物图库。每个视频仍为一个 photos 媒体记录，media_type=video，保留时长、人工封面与识别错误；与照片共用日期、搜索、宠物、回忆、收藏、增量去重和断开／恢复规则。未变化文件跳过哈希与推理；解码失败记录错误并避免每分钟重复推理，可精细重扫或修改文件重试。

默认采样：20 秒内每 2 秒，5 分钟内每 5 秒，更长每 10 秒，初采样最多 120 帧，超限改为均匀覆盖全片；发现宠物的附近按秒补采最多 60 帧。精细识别优先每秒初采样，同样有限额。采样帧不会增加独立媒体数量，不会靠同一视频的 5 帧生成新档案；重复时间的同框身份排他，不同时间允许属于同一身份，每个身份组单视频最多保存 8 个特征样本以控制权重。video_hits 和 video_observation_times 分别记录出现位置和区域时间，合并时仅将同时间区域视作共现冲突。

视频卡片显示时长，预览原生播放，点击宠物出现时间定位，可将当前画面设为视频封面；宠物／回忆也可选视频封面。原编码无法播放时按需生成 H.264/AAC 兼容副本（/data/video-playback），不修改原文件，首次准备较慢，副本增加应用存储，清空数据时删除。字幕／特殊编码兼容性不能保证，可下载原视频。FFmpeg 子进程有超时、取消与线程限制，缩略图并发限制为 2，采样任务逐帧响应暂停／取消。

`scripts/test_videos.py` 隔离验证多宠物时间、独立计数、去重、人工调整、封面、精细任务、取消和存储断开；`--real` 在 Linux 镜像使用真实 FFmpeg 编解码和 Range 请求。`scripts/check_video_gpu.py` 在独立容器、只读测试图片上真实生成黑屏→猫→刺猬视频并通过 Quadro M2000M 识别，验证两只命名宠物、出现时间及自动选封面，不改生产数据。`scripts/check_video_ui.py` 使用真实 H.264 视频验证播放、时间定位、封面、兼容播放、手机、回忆和宠物封面。

## 回忆分享与反向代理

回忆卡片和详情页的“分享”可创建随机链接，选择 7 天／30 天／永久，可选至少 4 位提取码及原文件下载开关（默认关闭）。每次创建生成独立的 256 位随机 token；设置→分享设置可查看所有链接并关闭。分享跟随整个回忆更新；移出的媒体立即不能再读取，删除／被合并掉的回忆会级联删除原分享，保留目标回忆的链接继续有效。

管理服务仍为 `192.168.1.80:8766`，独立只读访客服务为 **`192.168.1.80:8767`**。反代域名请指向 **8767**；这个端口仅提供 `/s/{token}`、`/api/public/shares/...`、静态资源和图标，没有管理 API。`ousepet.server` 同时管理两个 Uvicorn 子进程，先等待管理端完成数据库迁移再启动访客服务；访客模块不导入管理 API，不会重新初始化／中断扫描。Compose 映射两个端口，原图依然只读挂载。

设置→分享设置→分享域名，填写如 `https://photos.example.com`，只允许 HTTP/HTTPS 的域名或 IP（可含端口），不含路径。留空时复制当前访问主机的 IP／主机名与 8767 端口；配置后新复制的所有链接使用该域名。域名只改变链接地址，不配置 DNS、TLS 或反向代理。HTTP/IP 场景也支持复制链接，浏览器剪贴板不可用时回退到页面内复制。

访客不注册，不读取管理状态、存储路径、文件哈希或宠物档案，只能读取当前 token 所属回忆中的可用媒体；每个 JSON／缩略图／预览／下载请求都重新检查有效期、关闭状态、提取码会话和实时成员关系。提取码使用 PBKDF2-SHA256、独立盐与 120000 次迭代；会话为绑定 token 和当前码指纹的 HMAC 签名 HttpOnly/SameSite=Lax cookie（24 小时，仍受分享有效期约束），反代传 `X-Forwarded-Proto: https` 时添加 Secure。错误提取码按分享和连接 IP 限制每分钟 10 次，访客端不信任任意转发 IP 头。

访客照片预览最大 1920 像素并去除 EXIF；视频按需生成移除来源元数据的 H.264/AAC 浏览副本，支持 Range，缓存位于 `/data/share-cache`，清空数据时清理。关闭下载禁止原文件下载接口并隐藏下载入口；观看本身无法阻止保存已经加载的画面。分享响应禁用缓存，设置 no-referrer 与 noindex。生产部署不自动创建或发布任何已有回忆，需用户点击创建链接。

`scripts/test_sharing.py` 验证访客／管理隔离、成员权限、原文件下载、提取码与防猜测、关闭／过期、域名和级联删除；`scripts/test_sharing_real.py` 在镜像中真实验证 FFmpeg 公共视频预览、Range、移除来源标题和 GPS、原文件不变；`scripts/check_sharing_ui.py` 用独立管理和分享端口验证创建／复制、提取码、访客照片与视频、关闭、配置域名和手机界面。
